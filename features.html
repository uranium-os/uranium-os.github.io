Features

Frames and undo

scram frame [-m NOTE] [LABEL], scram
Takes a read-only btrfs snapshot of @ and @home into .scram/ on the top level, mounted at /run/scram/top. The id is the date and time followed by the label. A package change, a restore and a flash leave a frame behind.
rod, silo, rod
rod +i, +r and +u take a frame labelled pre-install, pre-remove and pre-update when scram is on the path. silo takes pre-container and pre-container-remove. With rod -n no frame is taken.
autoframe service, services
Sleeps for an hour, then runs scram auto 48: a frame labelled auto, and the oldest automatic frames beyond the newest 48 are deleted. scram keep [FRAME] protects a frame from pruning.
scram boot [N], /boot/limine.conf, boot
Copies the kernel and initramfs to the boot partition and writes a menu with the current system, the newest N frames (default all) and a rescue shell. A frame entry boots a writable copy of that frame (uranium.frame=ID) and drops the copy at the next frame boot. The menu is also on the serial console. rod runs scram boot after a successful install, removal, upgrade or set install.
Kernel per frame, scram
A frame stores the vmlinuz and initrd of it's profile under boot/. The boot partition keeps one copy of each distinct kernel, at most three besides the current one (SCRAM_KERNELS). A frame that would need a fourth boots with the current kernel.
Rescue shell entry
The menu entry with uranium.shell stops in a shell in the initramfs before the root is mounted.
scram flash [--boot] [--root] [FRAME]
Replaces the live subvolumes with copies of a frame. --boot schedules it for the next boot, which is the form for a running system. --root replaces @ only. A pre-flash frame is taken first, and the command prints how to undo it.
scram try, commit, discard, scram
scram try [--check CMD] CMD runs a command in a chroot of a copy of @. If the command or the check fails the copy is deleted and the system is untouched. scram commit [--boot] [--force] swaps the copy in; it refuses when the live system changed after try. rod +u does its upgrade this way and prints a message.
scram confirm, scram verify, trial service, geiger
A committed update boots on trial. verify waits 300 seconds, runs geiger up to three times 30 seconds apart, confirms the update when it passes and reboots when it does not. If the next normal boot comes without a confirmation, the initramfs flashes @ back to the pre-commit frame and takes a pre-revert frame first. A system that cannot boot reverts at the second power cycle.
scram restore PATH [FRAME]
Replaces a file or directory with its copy from a frame, after a pre-restore frame. It refuses an excluded path.
scram roll, log, status, diff, cat, blame, doctor
List frames, list them with the number of changed files and their notes, show the layout and the prune policy, list the files that differ from a frame or between two frames, print a file as it was in a frame, list the frames in which a path changed, and check the layout and the boot menu. doctor exits with 1 on a failed check.
scram scratch [-f FRAME] [COMMAND]
Runs a shell, or the command, in a chroot of a copy of @ or of a frame. The copy is deleted afterwards and the shell prompt shows scratch.
scram bisect GOOD BAD COMMAND
Binary search for the first frame between two in which the command fails. The command runs in a copy of each frame it visits.
scram send [-p PARENT] [FRAME], scram receive, backups
Write a frame to standard output as a stream, only the difference to a parent frame with -p, and create a frame from a stream on standard input.
/etc/scram, /etc/scram.d/, ~/.config/scram, scram apply
A line -PATH excludes a directory and +PATH includes it again. Excluded directories become nested subvolumes, which snapshots leave out. The stage excludes /rod/nixpkgs, /var/cache and /var/tmp. Paths with spaces are not supported.
SCRAM_HOOKS
Scripts in /etc/scram.hooks/pre-frame.d and post-frame.d run around every frame.

Packages

rod +i PACKAGE|@SET... [-i NAME...], rod
Installs packages from the nixpkgs index, or a recipe in /rod/recipes/NAME.nix, and releases a hold. A set is a file in /etc/rod/sets with one package per line. -i leaves the named members out; every name has to be given by the packages or sets of the line, and rod stops with an error otherwise.
rod +r PACKAGE|@SET... [-r NAME...]
Removes packages and keeps the named members of a set. A package that is named and not installed is an error. Reinstalling is rod +r NAME +i NAME.
rod +t PACKAGE..., rod -t PACKAGE...
Hold a package at its version and release the hold. The holds are in /rod/holds, and rod +u skips them.
rod +u, rod +h
Sync the index and upgrade every package that is not held, in a copy of the system. +h lists what an upgrade would change.
rod -n
As the first argument, shows what +i, +r or +u would install, remove or upgrade and how much it would download, and changes nothing. Other operations refuse it.
rod +s [URL|REV], rod +p
Fetch the index into /rod/nixpkgs, or pin it to a 40 character nixpkgs revision. +p shows the url, revision and date in /rod/nixpkgs/.pin.
rod +o FILE, rod +a FILE
Write the installed names, the holds and the index revision to a file, and install the set that a file describes after syncing the index to its revision. The package set is reproduced, not the builds bit for bit.
rod +f WORD, +n PACKAGE, +l [explicit]
Find a package by name or description, show the name, description and homepage, and list the installed packages, or only those asked for from /rod/installed.
rod +y, -y, +z, +w, +q, +x
Show what a package needs as a tree, what needs it, the size of the profile or of a package with its dependencies, which package a file belongs to, the files of a package, and why a package is installed.
rod +k
Checks every file of the profile and its dependencies against the hashes of the store. It reports that the profile is intact, or lists the damaged paths.
rod +e PACKAGE... [-- COMMAND], rod +d PACKAGE... [-- COMMAND]
A shell, or a command, with the packages on the path and nothing installed. +d adds the build toolchain with the headers and libraries of the packages.
rod +c [old]
Deletes packages no generation uses; with old, old generations first.
Recipes, recipes
A Nix expression in /rod/recipes is installed under its name before the index is searched. When a source hash is wrong and the recipe has one hash line, rod prints the real hash and on a terminal offers to write it into the file.
Signature checks
Nix checks each downloaded package against the signing key of cache.nixos.org. This is the Nix default; /etc/nix/nix.conf only names the cache.
rod bootstrap, developers
A shell rod installs the first packages while the stage is built. It knows +i +r +s +l only. The full rod comes with the uranium-tools package.

Isolation and security

hazmat [-n] [-r PATH] [-w PATH] PACKAGE... -- COMMAND, hazmat
Runs a command in a bubblewrap sandbox with --unshare-all, a read-only system, an empty /home and /tmp. -r and -w bind a path read-only or writable. -n removes the network.
silo [-n] NAME [PKG...] [-- CMD], silo
Containers with their own profile, hostname, /etc and home in /rod/containers/NAME. silo lists them and silo -d NAME deletes one. Frames include containers, because they are in @.
sandbox file in a service directory, hazmat -s
Lines ro PATH, rw PATH, net and nonet. A run script that starts with exec hazmat -s runs the daemon inside the sandbox, without the network unless net is given.
blastdoor allow|deny PORT[/tcp|/udp], list, reload, blastdoor
Edits the rules in /etc/nftables.d/. The base rules in /etc/nftables.conf drop incoming traffic except loopback, replies, ICMP, DHCP replies and ssh (new connections limited to 10 a minute). Forwarding is dropped and outgoing traffic is accepted.
doas, users
The only setuid program, in /rod/wrappers. /etc/doas.conf is permit persist :wheel.
/etc/sysctl.conf, /etc/cmdline, security
Sysctl settings such as kernel.kptr_restrict = 2, kernel.yama.ptrace_scope = 2, kernel.unprivileged_bpf_disabled = 1 and fs.protected_regular = 2, and the kernel arguments slab_nomerge vsyscall=none debugfs=off randomize_kstack_offset=on. /home is mounted nodev,nosuid and /boot nodev,nosuid,noexec.
Kernel configuration, kernel
Randomized base and memory layout, write-protected kernel text, strong stack protector, hardened usercopy, zeroed allocations and call-used registers, a hardened slab freelist, list hardening, Yama, Landlock and no kexec, hibernation, /proc/kcore or binfmt_misc. User namespaces are on, because bubblewrap needs them.
Encrypted root, partitioning
The initramfs unlocks the LUKS container named by uranium.luks= with a passphrase (three tries) or a key file given by uranium.luks.key= before it looks for the root. The manual install can create it; the installer cannot.
Release signatures, download
SHA256 is signed with signify, and the key is in /etc/signify/uranium-0.1.pub.
geiger, geiger
Prints ok, warn or FAIL for services, the network address, root and boot partition use, the firewall, the frames, the package index age and the kernel. It exits with 1 when a check is FAIL.

Install

uranium-install [--config FILE] [-y], live medium
A menu-driven installer for keyboard, hostname, time zone, root password, user, software and disk. An answer file with DISK HOST USERNAME USERPASS ROOTPASS ZONE KEYMAP PROFILE EXTRA FIRMWARE runs it without questions, and -y skips the confirmation. The profiles are minimal, server (adds the ssh server), tools and dev. It needs UEFI.
Manual install, manual install
Unpack the stage tarball into a filesystem you made, with the chroot, configuration, boot menu and optional encryption described step by step.
setup [--hostname NAME] [--user NAME] [--password-stdin] [--root-password-stdin] [--timezone ZONE] [--keymap MAP] [--ssh], first steps
Sets the hostname, creates a user in the wheel group, sets the passwords, the time zone and the keymap, and enables sshd. With no options it asks. The installer uses it.
uranium-chroot ROOT [COMMAND], genfstab ROOT
Enter a mounted system with /dev, /proc and /sys bound, and print an fstab for the mounts under ROOT by label.
uranium-man [PAGE]
Opens a page of the handbook that is on the live medium.

System

Services, services
A directory in /etc/sv with a run script, enabled by a link in /etc/service and controlled with sv. A log/run script sends output to svlogd in /var/log/NAME. Enabled: autoframe, crond, dhcp, getty-tty1, getty-ttyS0, ntpd, trial. sshd is enabled by setup --ssh or the server profile.
dhcp, ntpd, network, time
udhcpc on the first network device (IPv4), and busybox ntpd against pool.ntp.org and time.cloudflare.com.
/etc/crontabs/root, cron
fstrim -a on Sundays at 04:00 and btrfs scrub start -B / on the first of the month at 05:00.
zram swap, storage
A zram device of half the memory, enabled at priority 100 by /etc/rc.
/etc/keymap, keyboard
The console keymap that /etc/rc loads with loadkeys.
Kernel, kernel
A recipe: mainline source, the configuration in recipes/linux-uranium.config, every driver built in and no modules. Replace it with a recipe of your own by the same name in /rod/recipes.
scram doctor
Checks the subvolumes, the excluded subvolumes, the scheduled boot action, the boot menu and the free space.
Manual pages, system
man uranium, rod, scram, setup, silo, hazmat, blastdoor, geiger, uranium-man, and bash completion for rod. fastfetch prints a system summary at login, with a tip from /rod/share/tips.
